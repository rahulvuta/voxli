Format: what AI produced, how it was checked, what the check found, decision.

| # | AI produced | How checked | What the check found | Decision |
|---|---|---|---|---|
| 1 | Deepgram live client (URL params, auth, KeepAlive, CloseStream, Results mapping) written from memory of the API | Fetched the current Deepgram listen-streaming reference and compared message names and fields; then streamed `eval/clips/turns_2spk.wav` in real time against the real service | Params and message shapes matched the docs. `utterance_end_ms=1000` + `endpointing=300` alone never produced `speech_final` on clips with short pauses, so one caption grew for 12 s | Changed: added sentence splitting (pause >= 0.3 s after `.?!`) with a cut-off time so re-sent words are never emitted twice. | 2 | First version of that mapping emitted the same words in two different segments (finals re-sent by Deepgram) | Real stream plus a unit test that replays an interim followed by the matching `is_final` chunk | Duplicate "Hi." as a second segment | Changed: `_cut` filter, test `test_sentence_pause_splits_into_finals_without_resending_words` |
| 3 | `parakeet-mlx` streaming API (`transcribe_stream`) for the local fallback, based on the README | Read the library source; ran it on a clip | (a) Every GPU matmul raised a Metal "NAX" kernel error on this M5 / macOS 26.1 (MLX 0.32.4, latest). (b) Streaming-mode accuracy was poor ("I don't manage to find the rest of the yeah"). (c) Draft-token timestamps are relative to the draft window, so word times were wrong | Changed: (a) `MLX_METAL_GPU_ARCH=applegpu_g16s` set before `import mlx` on M5+ chips (verified a 64x4096 @ 4096x1024 matmul works); (b, c) dropped streaming. The utterance is re-decoded with the offline `generate()` every ~0.6 s for interims and once at VAD end for the final. Accuracy matches the offline model and timestamps are absolute. Interim decoding is throttled to one third of wall time |
| 4 | Silero VAD wiring (`VADIterator`, 512-sample frames) | Read the `VADIterator` source for return values; ran on clips | Works. On digital silence the model hallucinated a word ("Friday.") | Changed: skip decoding when RMS < 0.004 |
| 5 | Failover state machine (`failover.py`): audio cursor over `AudioBuffer`, replay on switch, watchdog, hand-back to Deepgram | Wrote 5 tests with fake engines (unreachable, dies mid-segment, stale results ignored, silent while speech, recovery hand-back) then ran real tests: invalid key, and a Deepgram socket closed mid-clip | Tests found two bugs in my code: a reattached session replayed 60 s of old audio (added `start_at`), and a status test exposed that the first `reconnecting` is deduplicated. Real runs: see replay evidence in the final report | Kept after fixes |
| 6 | Session rewrite (interim speaker from vendor hint map, active speakers, TTS windows, overlap background task, name suggestion undo, malformed message handling, resume) | pytest with `TestClient` for malformed input and resume, unit tests for suggestions and late merges, plus end-to-end `replay.py` runs on turn-taking, self-intro and overlap clips | Real runs showed false Deepgram "silent" failovers while the machine was loaded; event loop lag was measured (<150 ms in later runs) and `replay.py` now reports it | Kept; watchdog threshold left at 2 s |
| 7 | OpenRouter `deepgram/nova-3` request format | Fetched the OpenRouter STT docs, then made a real call | `verbose_json` + `timestamp_granularities:["word"]` returns word times; works (1.3 s for 6 s of audio) | Kept |

Notes
- No secrets are printed or logged: Deepgram connect errors only report the exception class and HTTP status.
- Provisional interim speaker uses only a map from Deepgram's diarization label to a speaker that an earlier confident final established, always flagged `speaker_uncertain`. It does not call `identity.assign` on interims (that would change identity state).
