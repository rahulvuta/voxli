# Design (UI redesign) dev log

Format: what AI produced -> how it was checked -> what the check found -> kept / changed / rejected.
All code was written by Claude (Sonnet) in this session. Checks were done in the built-in browser at 375x812 and 768x1024, dark and light, `?mock=1`, against the real backend for the TTS endpoints (it was running on :8000). `npm run build` and `npx oxlint` pass. Final screenshots: `web/screenshots/v2/`; the old UI is kept as `web/screenshots/before-*.jpg`.

1. **Design system (`src/style.css`).** AI produced CSS custom properties: Atkinson Hyperlegible (self-hosted woff2 from Google Fonts' gstatic source plus the OFL.txt from the googlefonts/atkinson-hyperlegible repo, Braille Institute copyright), type scale, 8-pt spacing, three surfaces (`--s1/--s2/--s3`) instead of borders, two radii (`--r`, `--r-lg`), a warm near-black dark theme, a light theme, one violet accent, eight Okabe-Ito-derived speaker colours tuned per theme. Checked with a Python WCAG-contrast script over every token pair, then in the browser with a computed-style audit (walks every text node, composites translucent backgrounds, applies ancestor opacity) over People, Conversation, Room, Settings and Catch-up in dark, light and both high-contrast variants. Found: first light palette had `--ok`/`--dim` at 4.0-4.4:1 on the raised surfaces, and two light speaker colours at 4.4:1 as rails. Fixed by darkening those tokens. Final minimum text contrast: dark 5.98:1, light 5.35:1 (disabled Speak button, which is exempt, is the lowest), high contrast >= 10.9:1. Kept.
2. **Design call that departs from "no borders".** Text inputs, switches, radios and the composer field keep a 1.5 px `--line` outline (>= 3:1 on every surface) because WCAG 1.4.11 needs form controls to be identifiable without relying on a 1.2:1 surface step. Cards, toasts, sheets and chat turns are borderless. Kept, deliberate.
3. **Identity (`palette.ts`, `ui.tsx` Avatar/ShapeMark).** Every speaker gets a colour, one of eight shapes (circle, square, hexagon, diamond, octagon, pentagon, shield, triangle) and their initial. State is a ring around the avatar: glow = speaking, dashed = unsure. "Shape only" mode swaps colours for one neutral. Checked in screenshots and in the Settings preview row. Found: overlapping avatars in the strip hid the initials and the active ring covered neighbours, so the strip no longer overlaps. Kept.
4. **Layout: top bar, People, Conversation, Room.** AI produced a two-row top bar on phones (wordmark, status dot, Catch me up, Settings; then avatar strip and view switch) that becomes one row from 720 px. Measured: the caption stage is 80.3 % of the 812 px viewport with the composer closed. Screenshot critique found and fixed: (a) the first single-row bar overflowed at 375 px when the Room button appeared, so it became two rows; (b) tags such as "speaking" truncated names to "S...", so state moved to a small line under the name; (c) "Unsure who" appeared twice in a card, kept only the tappable one beside the sentence; (d) the 5+ people grid collapsed the previous lines because its rows are auto height (CSS override, not visually verified because the mock only has four people); (e) tablet captions looked small in large cards, so captions scale 1.3x from 720 px; (f) the sentence that overflows a card is clipped from the top so the newest words stay visible (column-reverse trick). Kept after fixes.
5. **Relationships.** "to Maya" / "cut in on Maya" are small muted tappable lines (jump scrolls and flashes the target, or opens that person's history at that line when the target is not on screen); interrupted sentences end with an em dash plus "interrupted by C"; overlaps are stacked turns inside a thin bracket labelled "at the same time"; low-confidence words keep a dotted underline. Verbatim rule unchanged: text is rendered from `utterance.text` only, confidence only styles the same tokens. Checked in the Conversation screenshots (dark and light, phone and tablet). Kept.
6. **Toasts (`Toasts.tsx`).** One toast at a time above the composer, over the captions' bottom edge so nothing is pushed. Order: mic blocked, short notice, name suggestion, reconnecting, offline captions, engine switch, mono, busy room. Info toasts can be dismissed and stay away until the condition ends. Screenshots showed two stacked toasts covering about a quarter of the feed, so the limit is one and the copy was shortened. Also found that the new "Using phone voice" notice was hidden behind a pending suggestion, so notices now rank first (they clear after 7 s). Kept.
7. **Composer (`Composer.tsx`).** Pill input with Suggest and Show-to-them icons inside, a large Speak button (disabled state still reads at 5.4:1), quick-phrase tray opens on focus or Suggest and closes on outside tap or Escape; custom phrases still in localStorage (`settings.phrases`). Checked by typing and tapping in the browser. Known cost: with the tray open the captions shrink to about 58 % of the phone screen (and a real on-screen keyboard takes more); the tray only exists while composing. Kept.
8. **Voice (`tts.ts`).** AI produced: POST /api/tts, play the returned MP3 through one shared Audio element, `tts_start` right before playback and `tts_end` when it ends (or is stopped), 6.5 s timeout, any non-200/timeout/play error falls back to speechSynthesis (prefers voices named Premium/Enhanced/Natural/Google) and shows "Using phone voice"; voice picker from GET /api/tts/voices with a preview button per voice, choice saved in settings; `/api` added to the Vite proxy. Checked: against the real backend `GET /api/tts/voices` and `POST /api/tts` both returned 200 in `?mock=1`, the picker listed the ten voices, Speak produced the YOU line. Fallback checked by stubbing `fetch` to return 502 and `speechSynthesis.speak`: the phone voice was called and the Speak button recovered. Found: the server takes several seconds, so Speak flips to Stop immediately (state set before the fetch). Not verified: audible playback (headless pane), the silent-clip unlock trick on real iOS Safari, and `tts_start`/`tts_end` ordering against the real session mute window.
9. **Start screen, settings, sheets.** Inline SVG illustration (phone on a table, four caption cards), three steps, one big Start button, a one-line privacy note with a "Learn more" expander, demo link. Settings grouped Display / Voice / Privacy with live previews (caption sample at the chosen size, theme switch, speaker-shape row). Person history sheet (newest first, rename and merge inside), catch-up sheet (verbatim first, labelled AI summary), show-to-them (large text). Screenshot found the native radio buttons almost invisible on the dark surface (custom radios with the 3:1 outline) and an unwanted focus ring on the sheet's close button (the dialog itself takes focus now). Kept.
10. **Polish.** Screen Wake Lock while listening with re-acquire on `visibilitychange`; web manifest and generated icons (PIL, 192/512/180) for home-screen install; safe-area insets; `data-theme` set before first paint to avoid a flash; 150 ms fades only, honouring `prefers-reduced-motion` and the in-app switch. Checked: manifest and icons are served (200), the build passes. Not verified: that a lock was actually granted, or home-screen install on a device.
11. **Mock (`mock.ts`).** Reworked to queue events by time so `&from=33` can start mid-script (used for screenshots); added more lines, a reply chain and a busy-room period. It showcases the auto name with Undo, a reply, an interruption, an overlap, an unsure speaker with low-confidence words, a name suggestion needing confirmation, and the busy-room toast. Found: the fast-forwarded events ran synchronously, so React StrictMode's double mount duplicated every speaker ("earlier" cards); they now run from a timer that `close()` cancels. Found: `&mono=1` still gave speakers a direction (Room button stayed), fixed in `upsert`. Kept.
12. **Accessibility checks run.** DOM audit of 23 interactive elements: all have an accessible name; none under 24 px (primary controls 36-52 px); one `h1`; landmarks `header`, `main`, labelled `form`. Native `<dialog>` sheets (focus trap, Esc), aria-live announcer unchanged, status dot has text in its label and a different shape per state, speaker colour never the only cue. Reduce-motion and high-contrast switches checked in the audit. Not done: a screen-reader pass (VoiceOver/TalkBack) and a real colour-blind simulation; the palette is derived from Okabe-Ito and every speaker has shape plus initial.
13. **Cleanup.** Removed the old components (Banners, Captions, Header, ReplyBar) and their CSS; temporary HTTP vite config used for screenshots was deleted. No git commits made.
