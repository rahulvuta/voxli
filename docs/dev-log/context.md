# Dev log: context agent (Card 4)

Format: what AI produced / how checked / what the check found / kept, changed, rejected.

1. **Engine + prompts (Claude wrote the first draft).** Checked by 12 mocked-HTTP pytest cases (`backend/tests/test_context.py`): invalid ids dropped, forward/same-speaker interrupts rejected, hallucinated name rejected, timeout/500/non-JSON/empty key -> no events, in-flight coalescing, introduced name goes to next different speaker, history never mutated. Kept; the in-flight case caught that skipped utterances must stay un-annotated so the next window covers them (design now works that way).
2. **Structured output.** Did not assume support: queried OpenRouter `/models` (both Haiku 5.5 and Sonnet 5.5 list `response_format` + `structured_outputs`) and made a live call. First draft added `provider.require_parameters=true`; live run returned HTTP 404 for every call (no endpoint satisfied it). Rejected that flag; we still parse and validate every reply ourselves, so a provider ignoring the schema degrades to "no events".
3. **Verbatim guard (`context/guard.py`).** Events are checked against an exact key whitelist, existing ids, `^t\d+$` thread ids, names that appear as whole words in the evidence utterance. Tested with a rewritten-text field, unknown id, free-text thread, hallucinated name, extra catch-up field: 5/5 rejected. An eval bug (the guard run over merged snippets with colliding ids, 37 false violations) was caught by reading the output; fixed to run per snippet -> 0 violations.
4. **Name rules.** Self-intro auto-applied; introduced -> pending, suggested (not auto) to the next different real speaker within 3 turns; corrections need a validated target speaker; vocatives and mentions ignored. First eval run of "Dr. Okafor" failed because our prompt said "first name"; prompt reworded to allow title+surname. Label for that item changed from `Okafor` to `Dr. Okafor` after seeing both models answer it (a form choice; disclosed here because the label was edited after a model run).
5. **Eval sets** (`eval/context/make_sets.py` -> names.jsonl 50 items, replies.jsonl 12) hand-written by us with AI help for coverage ideas; labels reviewed by hand. Text is typed, not real ASR output, so scores are optimistic. Both models score ~100% so the set cannot separate them on accuracy; it does show cost (16x) and latency.
6. **Live smoke of catch_up / suggest_replies** on a 5-utterance snippet: ids and speakers validated; Haiku once misattributed who should bring slides in a summary (summaries are AI text and labeled as such in the UI). Summaries over 15 words are truncated to 15, which can cut a sentence mid-way.
